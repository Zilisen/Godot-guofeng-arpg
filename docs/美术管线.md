## 1. 风格定位

### 1.1 《暖雪》和《哈迪斯》到底差在哪

| 维度 | 《暖雪》 | 《哈迪斯》 | 对单人的含义 |
|---|---|---|---|
| 角色 | 2D 手绘，厚涂 + 水墨边缘，暗黑国风 | 2D 手绘，粗墨线 + 平涂 + 少量渐变，美漫感 | 都要"手绘感"，但哈迪斯线条更硬、更依赖线稿 |
| 场景 | 手绘分层背景，数量少、复用高 | **3D 低模 + 手绘贴图**，摄像机可动、实时灯光 | 3D 场景对单人是奢侈品，不做 |
| 色彩 | 灰黑主色，刀光/技能才高亮 | 高饱和互补色（红/青/金），整体明亮 | 暖雪路线更适合小团队：**省在场景，赢在特效** |
| 光影 | 基本烘焙在贴图里，靠粒子造氛围 | 引擎实时光影，角色融进 3D 空间 | 只给主角/Boss 做 2D 法线光照 |
| 叙事包装 | 皮影戏开场、毛笔字 UI、印章 | 美漫分镜式对话框、角色立绘特写 | 国风的"贵气"很大一部分在 UI 和包装，不在模型面数 |
| 产能门槛 | 中（场景可复用，角色量大） | 高（3D 场景 + 大量角色 + 全语音） | 暖雪是更现实的对标 |

参考：[《暖雪》主创访谈（TapTap）](https://www.taptap.cn/moment/415958402821262549)、[游研社：暖雪的视觉辨识度](https://www.yystv.cn/p/8729)

**关键观察**：《暖雪》被夸"画风好"，实际靠三件事——灰黑底、毛笔字 UI、刀光高亮；它的场景数量并不多。这三件事里有两件是**低成本高回报**的，正好适合你。

### 1.2 你的方案：减法国风

一句话：**"墨底、厚涂人、亮刀光"**。画面 60% 是低饱和墨灰，30% 是中间调材质，10% 是高饱和技能色。

**做什么（按优先级）**

1. **角色厚涂拆件**：3–4 层明暗 + 1 层边缘光，不追求厚涂细节堆叠；靠剪影和配色区分角色。
2. **统一的描边规则**：外描边 2 px（@1x），颜色取主色明度 −60%，**不用纯黑**。
3. **技能特效高饱和 + 硬边 + 发光**：这是最便宜的辨识度来源，也是动作肉鸽的爽点。
4. **宣纸/绢布质感的 UI 底 + 毛笔标题 + 朱红印章**：一次性投入，长期复用。
5. **粒子氛围**：雪、灰烬、香火、落叶；一个 `GPUParticles2D` 场景复用到所有区域。

**克制什么（明确不做）**

| 不做 | 原因 |
|---|---|
| 4/8 方向角色 | 工作量 ×4；横版/斜 45° 只需左右翻转 |
| 全场景 3D | 单人没有场景 TA 产能 |
| 布料/头发物理 | Spine 网格 + 物理约束的调试成本极高，改用 3–4 段骨骼手 K |
| 全角色 2D 法线光照 | 法线图让每张图工时 +30–50%；只给主角/Boss |
| 每个 Boss 独立骨架 | Boss 共用"人形/兽形"两套基础骨架，换皮 + 加部件 |
| 逐帧动画做杂兵 | 8 帧攻击 × 7 种敌人 = 56 张画，改一次动作全废 |
| 多套 UI 皮肤 | 一套 9-slice + 换色即可 |

### 1.3 辨识度来自哪 4 个要素

| 要素 | 具体做法 | 量化标准 |
|---|---|---|
| **调色板** | 固定 6 色：墨底 `#14161A`、纸白 `#E8E2D4`、朱砂 `#B23A2E`、石青 `#3C7A8C`、金 `#C9A227`、技能冷光 `#DFF6FF` | 任意截图里高饱和像素占比 < 15% |
| **笔触** | 只允许 3 支笔：干墨勾线、湿墨铺色、飞白 | 所有角色共用同一套笔刷文件 |
| **剪影** | 任何角色缩到 128 px 高仍能认出 | 3 秒剪影测试，5 人里 4 人认对 |
| **特效色彩** | 技能色只有 3 种：冷青（普攻）、朱红（爆发）、金（大招/治疗） | 同屏特效色不超过 3 种 |

### 1.4 最容易做崩的 5 处 + 自检方法

| 崩点 | 表现 | 自检（10 分钟可做） |
|---|---|---|
| 画师风格不统一 | 每个角色饱和度/线宽/笔触都不一样 | 把 6 个角色并排缩到 128 px，眯眼看：谁最"跳"就先改谁 |
| 角色与场景清晰度不一致 | 角色锐、背景糊，像贴纸 | 1080p 全屏截图，放大 200% 看边缘像素密度是否接近 |
| 特效色过多 | 画面糊成一团，看不清敌人起手 | 灰度化截图：如果看不清攻击预警，就是特效过量 |
| 描边不统一 | 有的 1 px 有的 4 px，有的纯黑 | 统一用同一个描边 shader/材质，禁止手画描边 |
| 光源方向不一致 | 角色左上打光，场景右上打光 | 定死"主光左上 45°"，写进风格圣经 |

### 1.5 风格圣经（1 页，必须最先产出）

必须包含，且存成 `docs/风格圣经.md` + 1 张 A3 拼图：

- 6 色色板（hex + 使用比例）
- 3 支笔刷截图 + 笔刷参数
- 描边规则（宽度/颜色/例外）
- 主光方向 + 允许的辅光
- 分辨率与像素密度基准（见 3.1）
- 角色朝右、脚底原点规则
- 5 张"禁止示例"（AI 感厚涂、纯黑描边、荧光色、写实皮肤、像素化边缘）

## 2. 技术管线（Godot 4）

### 2.1 三条路径对比

| 维度 | Spine 官方运行时 | 内置 Skeleton2D + AnimationPlayer | 逐帧 |
|---|---|---|---|
| 现金成本 | Essential **$99**（促销 $69）；Pro **$449**（促销 $379） | 0 | 0（Krita 免费 / CSP 订阅） |
| 改一个动作的成本 | **低**：改骨骼关键帧，不重画 | 中：手动改关键帧/换件 | **高**：重画整段 |
| 表现力上限 | 中高（可网格变形，需 Pro） | 中低（无网格变形，飘带靠多段骨） | 高（可画任意形变） |
| Godot 成熟度 | 官方 GDExtension，持续维护 | 引擎内置，最稳 | 引擎内置，最稳 |
| 授权风险 | 需自购 Spine 授权才能随游戏分发运行时 | 无 | 无 |
| 学习曲线 | 2–4 周（有 2D 动画基础） | 1 周（但要懂节点结构） | 低（会画就行） |
| 文件体积 | 小（图集 + 骨骼数据） | 中 | 大 |
| 适合 | 主角、Boss、需要频繁改动作 | 杂兵、道具、机关、UI 动效 | 大招特写、登场、过场 |
| 不适合 | 完全不想学新工具 | 需要布料/头发形变的角色 | 任何需要反复迭代的量产内容 |

**Spine 授权要点（务必看清）**

- Essential **不含网格/权重等高级功能**；要做衣摆、飘带的网格变形必须上 Pro。
- 授权按**使用者人头**计费；每个打开 Spine 的人都要一份。外包画师有他自己的授权，**但你发布游戏仍需要你自己的授权**（运行时随游戏分发需要授权）。
- 未来更新免费；年收入 ≥ 50 万美元需 Enterprise。
- 来源：[Spine 购买页](https://esotericsoftware.com/spine-purchase)、[spine-godot 授权说明](https://github.com/EsotericSoftware/spine-runtimes/tree/4.2/spine-godot)

### 2.2 推荐组合（给这个项目）

| 内容 | 路径 | 理由 |
|---|---|---|
| 主角 | **Spine**（Pro 仅在需要衣摆/披风时） | 动作要反复调，改动作便宜是第一诉求 |
| 杂兵 6–8 种 | **1 套人形骨架 + 1 套兽形骨架，Spine 换皮** | 一套骨架 6 个动作，换 atlas 就是新敌人 |
| Boss 2–3 个 | **Spine + 2–3 段逐帧特写** | 主体骨骼动画，登场/大招插 8–12 帧逐帧提质感 |
| 场景 | 手绘分层 PNG + Godot 视差 | 不做 3D |
| 技能特效 | Godot `GPUParticles2D` + 序列图 + shader | 最便宜、最好改 |
| UI | 9-slice + 免费商用中文字体 | 一次性 |

**明确不建议**：用 Godot 的 Skeleton2D 做主角。它不是不能做，而是"改动作"这件事上比 Spine 慢 3–5 倍，正好踩中你最在意的点。Skeleton2D 留给杂兵/机关/UI 动效。

### 2.3 Godot 里的实际导入流程

#### A. Spine（spine-godot GDExtension）

1. **Spine 导出**：导出 `.json`（或 `.skel`）+ `.atlas` + `.png`（图集页）。建议图集最大 2048×2048，开启预乘 Alpha。
2. **装运行时**：下载与 **Godot 小版本**匹配的 spine-godot GDExtension，解压后把 `bin/` 放到项目根目录（出现 `bin/spine_godot_extension.gdextension`），重启编辑器生效。
3. **导入资源**：把 `.atlas`、`.json`/`.skel`、`.png` 拖进 `res://art/characters/hero/`；Godot 会生成对应的 Atlas / Skeleton 资源。
4. **搭节点**：新建 `SpineSprite`，在 Inspector 指定 skeleton 与 atlas；放到 `YSort` 节点下参与遮挡排序。
5. **播动画**：GDScript 里 `var state = $SpineSprite.get_animation_state()`，再 `state.set_animation("idle", true)`；用 `add_animation` + track 做上半身攻击 / 下半身移动的混合。
6. **挂点**：武器用 `SpineBoneNode` 跟随手部骨骼；刀光用 `SpineSlotNode` 插到指定 slot，保证渲染层级正确。
7. **碰撞**：在 Spine 里画 Bounding Box，运行时读取做受击框，不要手摆 CollisionShape2D。

> 注意：spine-godot 的 **GDExtension 不支持 C# 绑定**（C# 需自编译 C++ 引擎模块）。如果工程用 C#，这条路的维护成本会明显上升——**开工前先确认技术骨架用的语言**。

#### B. Skeleton2D + AnimationPlayer（零成本拆件）

1. 每个部件单独导出 PNG（`head`、`torso`、`upperarm_l`…），**不要在 Photoshop 里合并**。
2. 场景根放 `Skeleton2D`，逐级添加 `Bone2D`；每根骨的 rest 位置就是关节轴心（肩、肘、腕）。
3. 每个部件用 `Sprite2D` 作为对应 `Bone2D` 的子节点，`offset` 调到贴合。
4. `AnimationPlayer` 里对每根骨的 `rotation` / `position` / `scale` 打关键帧；循环动作首尾帧必须一致。
5. 需要形变的部件（披风）用 `Polygon2D` + `Skeleton2D` skinning，或直接拆成 3 段骨。
6. 优点：无授权、无版本耦合、导出即用；缺点：轴心要手调，改动作没有 Spine 的曲线编辑器顺手。

#### C. 逐帧

1. CSP/Photoshop 按 18–24 fps 画，**不要 12 fps**（动作游戏会显得卡）。
2. 导出**等距网格精灵表**（每帧同尺寸、同轴心），单帧建议 512–1024 px。
3. Godot 里 `AnimatedSprite2D` → `SpriteFrames` → "从精灵表添加帧"，按行列切；每帧可单独设时长。
4. 逐帧不要做循环移动动作（跑、走），只做一次性动作（大招、登场、死亡特写）。

### 2.4 版本坑（提前锁死）

- **Godot 小版本 ↔ spine-godot 运行时小版本必须匹配**；升级 Godot 前先确认运行时已发布对应版本，否则主角动画直接打不开。
- **Spine 数据版本 ↔ 运行时支持的 Spine 版本必须匹配**（例如 4.2 数据配 4.2 运行时），混用会加载失败。
- 建议：**锁定一个 Godot 版本到上线**，Spine 工程文件纳入版本管理（`.spine` 源文件 + 导出物都存）。

## 3. 资源规格（可直接发给外包）

### 3.1 全局基准

| 项 | 规格 |
|---|---|
| 设计分辨率 | 1920×1080；Godot Stretch Mode = `canvas_items`，Aspect = `expand` |
| 贴图倍率 | 源文件按 **2×** 输出，游戏内 50% 缩放；不要 1× 直接上，会糊 |
| 纹理过滤 | Linear + Mipmaps（手绘风必须开 mipmap，否则远距离闪烁） |
| 图集上限 | 2048×2048（兼容性最好）；主角最多 2–3 页 |
| 朝向 | 统一**朝右**；向左用 `flip_h` |
| 原点 | 角色**脚底中心**（0.5, 1.0）；飞行单位用身体中心 |
| 色彩空间 | sRGB；PNG-24 带 Alpha，不要 JPEG |
| 命名 | `chr_<角色>_<部件>_<序号>.png`、`anim_<动作>_<序号>`、`vfx_<技能>_<帧>.png` |

### 3.2 角色规格表

| 类型 | 屏幕高度 @1080p | 源贴图 | 拆件数 | 骨骼数 | 动画数 | 单动作关键帧 | 图集 |
|---|---|---|---|---|---|---|---|
| 主角 | 260–320 px | 1024 高/部件组 | 28–40 | 30–45 | 14–18 | 4–8 | 2–3 页 2048 |
| 杂兵 | 140–220 px | 512–1024 高 | 10–18 | 12–20 | 6–8 | 3–5 | 1 页 1024/2048 |
| 精英杂兵 | 同杂兵 ×1.2 | 复用杂兵 + 换色/加部件 | +2–4 | +2–4 | 6–8 | 3–5 | 复用 |
| Boss | 500–900 px | 2048 高 | 40–80 | 50–90 | 12–20 | 6–12 | 2–4 页 2048 |

> "拆件数"指独立 PNG 层数；"骨骼数"指 Spine 骨骼数量。给外包时直接把这四个数字写进需求，比说"做得精细点"有用。

### 3.3 动画清单（按动作肉鸽实际需要）

**主角（14 个，必做）**
`idle` / `run` / `dash` / `jump_up` / `fall` / `attack_1` / `attack_2` / `attack_3` / `heavy` / `skill_1` / `skill_2` / `hurt` / `die` / `cast`

可选 4 个：`ultimate`、`wall_slide`、`pickup`、`victory`

**杂兵（6 个，必做）**
`idle` / `move` / `attack` / `hurt` / `die` / `spawn`

**Boss（12 个，必做）**
`idle` / `walk` / `attack_1` / `attack_2` / `attack_3` / `skill` / `phase_change` / `hurt` / `stagger` / `die` / `intro` / `roar`

**时长基准**：普攻 0.25–0.45 s；重击 0.5–0.8 s；受击 0.15–0.25 s；死亡 0.6–1.2 s；登场 2–4 s。**Spine 导出的是时间曲线，不是帧序列**，帧率由游戏运行决定；Spine 内用 30 fps 预览即可。

### 3.4 拆件规范（外包最容易糊弄的地方）

- 每个部件**不裁切画布**，保持同一画布尺寸与相对位置（或提供统一坐标说明）。
- 图层命名即部件名：`head`、`hair_front`、`hair_back`、`torso`、`pelvis`、`upperarm_l/r`、`forearm_l/r`、`hand_l/r`、`thigh_l/r`、`shin_l/r`、`foot_l/r`、`weapon`、`cape_1..3`。
- **阴影层单独一层**，不要烘焙进颜色层；高光单独一层。
- 关节处**多画 3–5 px 重叠**，防止旋转露缝。
- 武器/飘带单独文件，附**握点坐标**（在画布中的 x,y）。
- 提供**分层 PSD**，不要只给合并 PNG。

### 3.5 法线与打光需求

| 对象 | 是否要法线 | 说明 |
|---|---|---|
| 主角 | **要** | 只做 1 张 atlas 页的法线；配合 Godot `PointLight2D` 做刀光扫过的高光 |
| Boss | **要** | 同上，Boss 战灯光是氛围重点 |
| 杂兵 | 不要 | 用统一 `CanvasModulate` + 轻微 rim shader 代替 |
| 场景前景 | 部分要 | 只给可交互/近景层 |
| UI | 不要 | — |

做法：用 SpriteIlluminator / Laigter / Materialize 从颜色图生成法线；Godot 侧用 `CanvasModulate` 定环境色 + `PointLight2D` 定主光，主光方向写死左上 45°。spine-godot 自带 `10-2d-lighting` 示例可参考。

**成本提醒**：法线不是"顺手做"，每张图要多 30–50% 工时，且外包经常不会。**默认不给杂兵做法线**。

### 3.6 场景 / 特效 / UI 规格

| 类别 | 规格 |
|---|---|
| 场景单屏 | 3840×2160（2×1080p），4–6 层：远景/中景/地面/前景遮挡/雾 |
| 场景 tile | 512 或 1024 px 模块化，接缝处留 8 px 重叠 |
| 视差 | 远 0.2×、中 0.5×、地面 1.0×、前景 1.2× |
| 技能特效 | 单帧 256–1024 px；8–16 帧 @24 fps；或纯 Godot 粒子 + shader |
| 受击特效 | 3–6 帧，128–512 px，白色/朱红闪光 |
| UI 图标 | 128×128 显示，源 256×256；统一 2 px 内发光描边 |
| 9-slice 面板 | 256×256，边距 32 px；必须可拉伸不变形 |
| 血条/资源条 | 1024×64，分 3 段（底/填充/高光） |
| 字体 | 标题 48–72 px 毛笔/宋体；正文 22–28 px；**只用免费商用字体** |

**免费商用中文字体（可直接用）**：[思源宋体](https://github.com/adobe-fonts/source-han-serif)（SIL OFL）、[思源黑体](https://github.com/adobe-fonts/source-han-sans)、[阿里巴巴普惠体](https://fonts.alibabagroup.com)、[霞鹜文楷](https://github.com/lxgw/LxgwWenKai)。方正/汉仪等商用授权通常按年/按用途计费（数千至数万元，**估算**，需逐款询价）。

### 3.7 交付文件清单（写进合同）

1. 分层 PSD（图层按部件命名，不合并、不裁切）
2. 每部件 PNG（透明，@1x + @2x）
3. Spine 工程 `.spine` + 导出 `.json/.skel` + `.atlas` + `.png`
4. 法线图（仅主角/Boss）
5. 动作清单表（动作名/时长/是否循环/关键帧数）
6. 握点与轴心坐标说明
7. 色板（hex）与笔刷说明
8. 授权文件/购买凭证

### 5.3 工时账（8–10 h/周 ≈ 40 h/月）

| 任务 | 自己做的工时（估算） |
|---|---|
| 学 Spine 到能独立做主角 | 20–30 h |
| 主角立绘 + 拆分（有绘画基础） | 30–50 h |
| 主角 Spine 绑定 | 8–12 h |
| 主角 14 个动作 | 30–45 h |
| 杂兵首只（含绑定） | 12–20 h |
| 杂兵换皮（每只） | 4–6 h |
| Boss（单只，含绑定+12 动作） | 40–60 h |
| 场景（单区域，4–6 层） | 25–40 h |
| 技能特效（每个） | 3–5 h |
| UI 整套 | 40–60 h |

**垂直切片（1 主角 + 3 杂兵 + 1 Boss + 1 区域 + 6 特效 + UI）**：约 **200–280 h** → 按 40 h/月 ≈ **5–7 个月**。
**全量（7 杂兵 + 3 Boss + 2 区域 + 12 特效）**：约 **700–900 h** → **18–22 个月**。

结论：**全职内容量已经超过你的业余时间，必须靠"买 + 换皮 + 砍量"三者叠加，否则项目会死在美术上。**

### 5.4 必须外包 vs 自己糊

| 必须外包（决定卖相） | 自己糊（省时间且不易露怯） |
|---|---|
| 主角立绘 + 拆分 | 杂兵换皮、改色、加部件 |
| Boss 立绘 | Spine 动作微调（复用现有动作改曲线） |
| 场景背景（1–2 张关键区域） | 技能特效（粒子 + shader） |
| UI 视觉设计（一次性） | 图标（买包改色） |
| 标题字/Logo | UI 拼接、9-slice 配置、字体排版 |

**外包"画"，自己"绑"**：绑定学习成本 20–30 h，但它是长期复用资产，且外包绑定报价往往比画还贵。
