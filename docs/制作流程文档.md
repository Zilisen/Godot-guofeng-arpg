## 1. 版本与语言锁定

### 1.1 为什么是 Godot 4.7.2，而不是"最新版"

1. **spine-godot 是 GDExtension，二进制与 Godot 小版本强绑定。** GDExtension 依赖引擎内部 ABI，Godot 从 4.x 的一个小版本到另一个小版本，扩展经常需要重新编译。运行时没发布对应版本时，主角的 Spine 资源直接加载失败——这是"游戏做完了但主角打不开"级别的风险。
2. **实测确认 4.7.2 有对应运行时。** spine-godot 官方下载地址是有规律的，可直接验证：

   ```
   https://spine-godot.s3.eu-central-1.amazonaws.com/{spineVersion}/{godotTag}/spine-godot-extension-{spineVersion}-{godotTag}.zip
   ```

   本机实测该路径存在且可下载（HTTP 200）：

   ```
   https://spine-godot.s3.eu-central-1.amazonaws.com/4.3/4.7.2-stable/spine-godot-extension-4.3-4.7.2-stable.zip
   ```

   约 17.9 MB。**换 Godot 版本前，先把这个 URL 里的版本号替换后访问一次，确认 200 再动手。**
3. **4.x 的 2D 能力已经够用且稳定**：`CharacterBody2D` 的 `move_and_slide`、`Area2D` 的 hitbox/hurtbox、`CanvasItem` 材质与 `ShaderMaterial`、`AnimationPlayer` / `AnimationTree`、`Resource` 数据驱动，都属于 4.x 成熟部分。选 4.7.2 而不是 3.x，是因为 3.x 的 GDExtension 生态（含 spine-godot 新版）已经停止跟进。
4. **不选 4.8 / 4.9 之类的新分支**：本项目 8–10 h/周，没有精力跟引擎升级。锁定一个版本做到上线，中途只在"运行时已发布对应版本 + 有必须修的引擎 bug"时升级。
5. **渲染器选 GL Compatibility 的理由**：2D 游戏不吃 Forward+ 的特性；Compatibility 对老显卡 / 核显 / 远程桌面更友好，导出包更小、启动更快。本机（RTX 4070 / OpenGL 3.3）与低配机都能跑。代价是不能用部分 3D 后处理——本项目不需要。

### 1.2 为什么是 GDScript，不是 C#

**硬约束：spine-godot 的 GDExtension 不提供 C# 绑定。**

- GDScript 可以直接调用 GDExtension 暴露的类（`SpineSprite`、`SpineSkeleton` 等），C# 则完全看不到这些类型。
- 如果工程用 C#，要么放弃 Spine（回到 Skeleton2D），要么自己编译 C++ 引擎模块并维护 C# 绑定——这不是单人业余项目该背的成本。
- **本工程从第一行代码就是 GDScript**，没有 C# 代码，不存在改造成本。
- 若未来确有 C# 需求（例如接第三方 C# 库），可行的折中是：**核心玩法与 Spine 表现留在 GDScript，工具链/编辑器插件用 C#**，两边通过信号或 `Callable` 通信。不建议反过来。

### 1.3 升级策略（写进团队约定）

```
升级 Godot 前必须依次确认：
1) spine-godot S3 上存在  <Spine版本>/<新GodotTag>/ 对应 zip（HTTP 200）
2) 主角 / Boss 的 .spine 工程能在新 Spine 编辑器里导出，且运行时版本匹配数据版本
3) 在分支上升级，跑完 tests/smoke_test.tscn 43 项，再截图比对画面
4) 升级后导出一次 Windows 包并启动验证
任何一步不过，回退。不要"先升级再想办法"。
```

### 2.2 为什么这样分

| 决定 | 原因 |
|---|---|
| `scenes/` 与 `scripts/` 分离，而不是"一个功能一个文件夹里同时放场景和脚本" | 场景文件会被频繁打开/保存，二进制冲突概率高于脚本；分开后 `git diff` 更干净。Godot 官方模板也是这个习惯。 |
| `scripts/core/` 独立于 `actors/` | 命中停顿、判定盒、输入缓冲是**跨角色复用**的基础设施。将来加 Boss、远程敌人、召唤物，直接复用，不改。这也是"手感原语"能独立调参的前提。 |
| `resources/` 单独放数值 | 数值调整是每天最高频的操作。`.tres` 可以在 Inspector 里改、可以复制出"重击""突刺"变体，不需要改脚本、不需要开场景。 |
| `assets/` 只放外部资源 | 美术资源的导入设置（filter/mipmap/压缩）由 Godot 的 `.import` 管理，和逻辑代码放一起会让人误以为可以手改。正式美术按 `assets/art/characters|environment|vfx` 三级分。 |
| `tests/` 入库 | 垂直切片阶段最怕"改手感把循环改崩"。有 43 项 headless 断言，每次改完 30 秒内知道有没有回归。 |
| `build/` 不入库 | 100 MB 的 exe 进仓库会直接把 Gitee 仓撑爆（见第 9 节）。 |

### 2.3 命名规范

| 类型 | 规则 | 示例 |
|---|---|---|
| 场景 | `snake_case.tscn`，与主脚本同名 | `player.tscn` / `enemy_melee.tscn` |
| 脚本 | `snake_case.gd`，类名 `PascalCase` | `player.gd` → `class_name Player` |
| 数值资源 | `<类别>_<语义>.tres` | `light_1.tres` / `skill_whirl.tres` / `room_2.tres` |
| 美术图 | `chr_<角色>_<部件>_<序号>.png` | `chr_hero_head_01.png` |
| 动画 | `anim_<动作>_<序号>` | `anim_attack_1` |
| 特效 | `vfx_<技能>_<帧>.png` | `vfx_whirl_03.png` |

### 2.4 版本库该忽略什么、为什么要忽略

`.gitignore` 关键项：

```gitignore
.godot/            # 编辑器缓存 + 导入产物
export.cfg         # 本机导出临时配置
build/             # 出包目录
*.exe *.pck *.zip  # 二进制产物
*.log
```

| 忽略项 | 原因 |
|---|---|
| `.godot/` | 它是**本机生成**的导入缓存（纹理压缩结果、脚本缓存、编辑器布局）。体积可达数百 MB；不同机器/不同 Godot 版本生成内容不同；提交后每次导入都会产生无意义 diff。**换机器后第一次打开编辑器会自动重建。** |
| `build/`、`*.exe`、`*.pck` | 二进制不可 diff、体积大、Gitee 免费仓容量有限。要发版就传网盘/Release，不进仓库。 |
| `export.cfg` | Godot 编辑器在本机生成的导出临时文件，和 `export_presets.cfg`（真正的预设，**要入库**）不是一回事。 |
| `*.import` | **不要忽略！** 很多人误以为它是生成物。`.import` 记录了导入参数（filter、mipmap、压缩模式），必须入库，否则换机器后贴图设置全丢。 |

`.gitattributes` 做两件事：统一 `text=auto eol=lf`（避免 Windows/Linux 换行符噪音），并把 `png/jpg/ogg/wav/ttf/tres/tscn` 声明为二进制，防止 Git 尝试做文本合并。

> 注意：Godot 4.4+ 会为脚本生成 `.uid` 文件，**要入库**。它保证"改了文件名/移动目录"后场景里对脚本的引用不断。

## 5. 手感原语的实现细节（调参入口）

所有参数都是 `@export`，在编辑器选中节点即可改，**不用改代码**。

### 5.1 命中停顿（hitstop）

**为什么不能用 `Engine.time_scale = 0`：**

1. 全局生效——UI、摄像机、粒子、音效全部定住，玩家体感是"卡了/掉帧"，而不是"这一刀很重"；
2. 所有依赖 `delta` 的计时器（含 `Tween`）会一起跳变，恢复时容易出现动作瞬移；
3. 音频不跟着停，观感割裂；
4. 调一个敌人的命中，全场景都受影响，无法做"轻击 0.05 s / 重击 0.12 s"的差异。

**本工程两种模式**（`scripts/core/hitstop.gd`）：

| 模式 | 做法 | 适用 |
|---|---|---|
| `ENTITY_ONLY`（默认） | 只把参与命中的两个实体 `process_mode = DISABLED` 一小段时间，其他敌人/场景/摄像机照常 | 普通命中、连段 |
| `GLOBAL_PAUSE` | `get_tree().paused = true` 的时间窗口，UI/摄像机设 `PROCESS_MODE_ALWAYS` | 大招、处决、Boss 破防 |

要点：

- 计时用**真实时间**（`HitStop` 自身 `PROCESS_MODE_ALWAYS`，`_process(delta)` 倒计时），从不改 `Engine.time_scale`；
- 冻结/恢复必须 `set_deferred("process_mode", ...)`——**命中发生在 `Area2D` 的物理回调里，引擎禁止在物理回调中直接禁用 `CollisionObject`**，否则报 `Disabling a CollisionObject node during a physics callback is not allowed`；
- 重复命中取"最长剩余时间"，不会叠成双倍停顿；
- 切场景/重开前调用 `HitStop.clear_all()`，避免状态泄漏。

参数：`HitData.hitstop`（普通 0.06，第三段 0.095）。

### 5.2 受击闪白与击退

- 闪白：`hit_flash.gdshader` 的 `flash_amount` 从 1 → 0 由 `Tween` 拉回，`flash_color` 默认近白；只影响该角色材质，不影响其他实体。
- 击退：`knockback * (1 - knockback_resist)`，玩家抗性 0.5，杂兵 0。击退走速度衰减，不是直接改位置，保证和碰撞/墙体不打架。
- 受击硬直：`hit_stun` 0.20 s；随后 `hurt_iframe` 0.55 s 保护帧，避免被围殴瞬间暴毙。

### 5.3 震屏

`screen_shake.gd`（`Camera2D`，组 `shake_camera`）：

- trauma 模型：`shake = trauma^2`，trauma 随时间按 `decay` 衰减；
- 偏移用多个不同频率的 `sin` 叠加，避免机械的左右抖动；
- 上限 `max_offset = 16 px`、`max_roll = 0.02 rad`，防止晕；
- 调用方式：`get_tree().call_group("shake_camera", "add_trauma", 0.15)`，由 `HitData.shake` 驱动。

### 5.4 输入缓冲（0.12–0.18 s）

`InputBuffer`（`RefCounted`，纯逻辑可单测）：

- 每次按下记录 `Time.get_ticks_msec()`；
- 状态机有空隙时 `consume()`：窗口内返回 true 并清空，**过期也清空**（避免"陈旧指令"在几秒后突然触发）；
- 默认 `input_buffer_window = 0.15`，导出范围 0.05–0.30；
- 玩家在待机/移动/后摇可取消阶段都会检查缓冲，所以"落地/后摇里提前按"不会吞键。

### 5.5 攻击取消窗口

`AttackData` 的阶段划分：

```
windup（前摇，无判定）
  → active（判定盒开启）
  → recovery（后摇）
cancel_from 之后：可被 闪避 / 技能 / 下一段普攻 取消
```

| 段落 | windup | active | recovery | cancel_from | 伤害 | 停顿 |
|---|---|---|---|---|---|---|
| light_1 | 0.07 | 0.07 | 0.20 | 0.16 | 12 | 0.06 |
| light_2 | 0.07 | 0.07 | 0.20 | 0.16 | 14 | 0.06 |
| light_3 | 0.16 | 0.10 | 0.34 | 0.30 | 24 | 0.095 |
| skill_whirl | 0.12 | 0.30 | 0.28 | 0.42 | 18 | 0.07 |

调参经验：

- `cancel_from` 太早 → 后摇没有"重量"，连段像滑冰；太晚 → 手感黏。**先按 active 结束 + 0.05–0.10 s 起调**。
- 第三段后摇 0.34 s、取消窗 0.30 s，保留约 0.04 s 的"不可取消尾巴"，让重击有收招代价。
- 连段窗口 `combo_window = 0.35 s`：上一段结束后的这段时间内再按普攻算下一段，否则从第一段重新开始。

### 5.6 判定盒的朝向与"Y 容差"

- 判定盒是 `Area2D` + `CollisionShape2D`，**偏移按 `facing` 旋转**，而不是简单 `flip_h`——斜向攻击才能打准。
- 玩家占地圆半径 46、受击盒半径 80 @ y=-140、普攻判定盒 280×190 @ (170, -60)：数值按 **1080p 尺度**取，不是 640×360 的小数值。
- 沿用 Unity 工程的设计意图：近战判定要有纵向容差（约角色半身），否则"明明砍到了却没打中"。这里通过判定盒高度 190 px 实现，不额外写 Y 差分逻辑。
- 调试时用 F2 看判定框；**测试里必须先确认 `facing.x > 0.9` 再打靶子**，否则朝向不对会打空（这是本次实际踩过的坑）。

## 6. 美术资源如何进 Godot

### 6.1 规格（与 `docs/美术管线.md` 一致）

| 项 | 规格 |
|---|---|
| 设计分辨率 | **1920×1080**，Stretch `canvas_items` + Aspect `expand` |
| 源图倍率 | 按 **2×** 输出，游戏内 50% 缩放（1× 直接上会糊） |
| 图集上限 | **2048×2048**（兼容性最好）；主角 2–3 页，杂兵 1 页 |
| 主角屏幕高 | **260–320 px** |
| 杂兵屏幕高 | **140–220 px** |
| Boss 屏幕高 | **500–900 px** |
| 朝向 / 原点 | 统一朝右，向左 `flip_h`；原点在脚底中心 (0.5, 1.0) |
| 格式 | PNG-24 带 Alpha，sRGB，不要 JPEG |
| 纹理过滤 | Linear + Mipmaps（手绘风必开，否则远处闪烁） |

**占位美术已按此比例制作**：玩家视觉高约 280 px、杂兵约 180 px，坐标直接是 1080p 数值。不采用"先做小尺寸再整体放大"的方案——那会导致后期所有速度、判定盒、镜头参数一起重调，等于把切片重做一遍。

> `docs/美术管线.md` 第 2.3 节里的 `res://art/...` 在本工程统一写作 `res://assets/art/...`（见 2.1 目录树），含义不变。

### 6.2 三条动画路线与推荐

| 维度 | Spine 官方运行时 | 内置 Skeleton2D + AnimationPlayer | 逐帧 |
|---|---|---|---|
| 成本 | Essential $99（Pro $449） | 0 | 0 |
| 改动作成本 | **低**（改骨骼关键帧） | 中（手调轴心/关键帧） | **高**（重画） |
| 表现力 | 中高（Pro 有网格变形） | 中低（无网格变形） | 高 |
| Godot 成熟度 | 官方 GDExtension，需版本对齐 | 引擎内置，最稳 | 引擎内置 |
| 适合 | 主角、Boss | 杂兵、机关、UI 动效 | 大招特写、登场 |

**推荐（本项目已定）**：

- 主角、Boss：**Spine**。动作要反复调，改动作便宜是第一诉求。
- 杂兵：**1 套人形 + 1 套兽形骨架，Spine 换皮**（换 atlas 就是新敌人）。
- 机关、UI 动效：`Skeleton2D + AnimationPlayer` 或 `Tween`。
- 大招特写：可插 8–12 帧逐帧提质感。

### 6.3 Spine 接入步骤（下一期执行）

1. Spine 编辑器导出 `.json`（或 `.skel`）+ `.atlas` + 图集 `.png`；图集 ≤2048，开预乘 Alpha。
2. 下载 **spine-godot-extension-4.3-4.7.2-stable.zip**（URL 见 1.1），解压后把包含 `.gdextension` 的目录整体放到工程根目录，保持包内相对结构，重启编辑器。
3. 验证：`ClassDB.class_exists("SpineSprite")` 为 true；编辑器节点列表能搜到 `SpineSprite`。
4. 素材放 `assets/art/characters/hero/`，拖入后生成 Atlas / Skeleton 资源。
5. 场景里用 `SpineSprite` 替换现在的 `Polygon2D` 占位（保留 `Hurtbox` / `AttackHitbox` / `Player` 脚本与碰撞体），放到 Y 排序节点下。
6. 动画切换：

   ```gdscript
   var state := $SpineSprite.get_animation_state()
   state.set_animation("run", true)
   # 上半身攻击 + 下半身移动：用 add_animation + track
   ```

7. 挂点：武器用 `SpineBoneNode` 跟随手骨，刀光用 `SpineSlotNode` 插 slot 保证层级。
8. 受击框：Spine 里画 Bounding Box，运行时读取替换手摆 `CollisionShape2D`（过渡期可先保留手摆）。

**注意**：Spine 动画是时间曲线，不锁帧；`AnimationPlayer` 的"帧"概念不适用。攻击帧数据（前摇/判定/后摇）仍由 `AttackData` 驱动，**不要**把判定窗口写进 Spine 动画事件里——两者解耦，改动画不用重调手感。

### 6.4 图集 / 帧动画 / 材质的导入要点

- 图集 PNG：`导入 → 过滤 = Linear`、`Mipmaps = 开`、`压缩 = VRAM Compressed（桌面）/ Lossless（像素风）`。手绘风不要用 Lossy。
- 逐帧：`AnimatedSprite2D` + `SpriteFrames`，"从精灵表添加帧"按行列切；单帧 512–1024 px。
- 材质：闪白 shader 挂在角色根 `CanvasItem.material` 上，复制材质实例（`material.duplicate()`）再改 `flash_amount`，否则会串到所有使用同材质的角色。

## 7. 数据与存档：Resource 还是 JSON

| 维度 | Resource（`.tres`） | JSON |
|---|---|---|
| 类型安全 | 强（`Array[AttackData]` 有校验） | 无（全是 Dictionary/float） |
| 编辑器体验 | Inspector 直接改，可拖引用 | 只能文本编辑 |
| 引用其他资源 | 原生支持（攻击引用 HitData） | 需要自己维护 id 映射 |
| 版本迁移 | 加字段有默认值；删字段需处理 | 全靠手写兼容代码 |
| 外部工具/表格 | 不便（需导出） | 方便（Excel/脚本生成） |
| 可读 diff | 一般（但稳定） | 好 |

**结论：**

- **游戏配置**（攻击帧数据、房间、敌人参数、掉落表）→ **Resource**。本工程已验证 `.tres` 里的类型化数组可正常加载：

  ```
  rooms = Array[ExtResource("2_room")]([ExtResource("3_r1"), ExtResource("4_r2")])
  ```

- **存档** → **Resource + `ResourceSaver`**（`user://save_slot_0.tres`）。理由：存档结构会随版本变化，Resource 加字段自动取默认值；JSON 需要手写迁移。存档里加 `save_version: int`，读到旧版本走升级函数。
- **JSON 只用于**：调试导出、外部表格/策划工具生成配置、需要人肉检查的日志。

存档注意：

1. 先写临时文件，再 `rename` 覆盖正式档，避免写入中断导致存档损坏；同时保留一份 `.bak`。
2. 不要 `ResourceLoader.load()` 用户可编辑路径的脚本类（存档只存数据，不存 `script`）。
3. 元进度（解锁、货币、图鉴）与单局进度分开存：`user://meta.tres` / `user://run.tres`。

## 8. 输入重映射与手柄支持

### 8.1 现状

`project.godot` 的 `[input]` 已配好 10 个动作，全部同时绑键鼠与手柄：

| 动作 | 键鼠 | 手柄 |
|---|---|---|
| `move_up/down/left/right` | WASD | 左摇杆 axis 0/1（deadzone 0.2） |
| `attack` | J | button 0（A） |
| `dash` | K / Space | button 1（B） |
| `skill` | L | button 2（X） |
| `restart` | R | button 6（Start） |
| `toggle_debug` / `toggle_shapes` | F1 / F2 | — |

### 8.2 约定

- **游戏逻辑一律走 `InputMap` 动作名**，不写死按键码，也不在脚本里判 `InputEventKey`。这样重映射只改配置。
- **轮询优先**：状态机里用 `Input.is_action_just_pressed()` / `Input.get_vector()`，不要用 `_input(event)`（见 3.4 的测试约束）。
- **手柄热插拔**：监听 `Input.joy_connection_changed`，重连后重新读取设备；不要缓存设备 id。
- **震动**：`Input.start_joy_vibration(0, 0.6, 0.3, 0.12)`（重击）或 0.04 s（轻击），在 `HitData` 命中处调用，和 hitstop 同窗口。
- **运行期重映射**（设置菜单，下一期做）：
  1. 用 `InputMap.action_erase_events()` + `InputMap.action_add_event()` 改绑；
  2. 存到 `user://input_bindings.cfg`（`ConfigFile`）；
  3. 启动时读取并应用，再 `InputMap.load_from_project_settings()` 是可选的"恢复默认"。
- **冲突检测**：同一个 `InputEventKey.physical_keycode` 已绑到其他动作时，提示并交换。用 `physical_keycode` 而不是 `keycode`，保证 A/W/S/D 在非 QWERTY 布局下仍是物理位置。
- **手柄 UI 导航**：菜单场景给按钮设 `focus_neighbor_*`，并保证默认焦点，否则手柄无法选菜单。

## 9. 版本库与二进制资源策略（Gitee 无 LFS 的坑）

### 9.1 坑在哪

- **Gitee 免费私有仓不支持 Git LFS**（和之前的 Unity 工程是同一个坑）。没有 LFS 意味着：每次提交一个 30 MB 的图集，仓库历史就永久多 30 MB，**删掉文件也不会变小**。
- 仓库容量与单文件大小都有上限（以 Gitee 当前政策为准，量级是单文件 ~100 MB、仓库 ~500 MB～1 GB）。一个 2D 动作游戏如果直接把 PSD、Spine 工程、未压缩图集全提交，几个月就会顶到上限。
- LFS 的本质是"指针 + 外部存储"；没有它，只能靠**约束入库体积**。

### 9.2 本项目策略

| 内容 | 是否入库 | 说明 |
|---|---|---|
| 代码 / 场景 / `.tres` / `.import` / `.uid` | ✅ | 文本，体积小，必须版本化 |
| `.spine` 工程源文件 | ✅ | 改动作的唯一源；单个通常几 MB |
| Spine 导出的 `.json/.skel/.atlas` | ✅ | 文本/小文件，几十 KB–几 MB |
| 图集 PNG（≤2048） | ⚠️ 有条件 | 单张控制在 **≤5 MB**；超过就拆页或降规格 |
| PSD / Aseprite 源 / 大尺寸原图 | ❌ | 放网盘/移动硬盘，仓库只存导出物；`docs/` 里记录备份位置 |
| 出包 `build/`、`*.exe/*.pck` | ❌ | 已 gitignore；发版走网盘/Release |
| 音频 | ✅ 但用 `.ogg` | 不要提交未压缩 `.wav`（BGM 一首就几十 MB） |
| 导出模板 / Godot 本体 | ❌ | 本机工具链，不入库 |

### 9.3 具体做法

1. **图集控制在 2048**：这既是美术规格，也是仓库策略。2048 的 PNG 通常 1–4 MB，可接受。
2. **提交前跑一次体积检查**：

   ```powershell
   Get-ChildItem D:\godot-guofeng-arpg -Recurse -File |
     Where-Object { $_.Length -gt 5MB } |
     Select-Object FullName, @{n='MB';e={[math]::Round($_.Length/1MB,2)}}
   ```

   出现 >5 MB 的非音频文件，先问"该不该入库"。
3. **不要在仓库里存中间产物**：PS 的 `*.psb`、Spine 的 `*.spine.bak`、录屏、截图全部 gitignore。
4. **备份分层**：Git（代码+小资源） + 网盘（大源文件） + 移动硬盘（每月全量）。**三者缺一不可**，因为 Git 仓库本身也可能丢。
5. **如果将来必须用 LFS**：把仓库迁到支持 LFS 的托管（GitHub 免费额度 1 GB 存储/1 GB 月流量，超出付费；或自建 Gitea + MinIO），或购买 Gitee 企业版。**不要在免费 Gitee 仓上"硬塞"大文件**。
6. **历史清理**：如果已经误提交大文件，用 `git filter-repo` 重写历史后强推（**先备份**，且这是破坏性操作，需全组确认）。

## 11. 坑点清单（本次实测）

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | PowerShell `Set-Content` 写入 **UTF-8 BOM** | `.tres` 报 `Parse Error: Expected '['`，引擎读不到资源 | 用 `UTF8Encoding($false)` 批量剥离 BOM；新建文件统一无 BOM UTF-8 |
| 2 | `Area2D` 先重叠、后开 `monitoring` | 不补发 `area_entered`，判定丢失 | `activate()` 后 `await get_tree().physics_frame`，再 `get_overlapping_areas()` 补扫 |
| 3 | 在物理回调里禁用 `CollisionObject` | 引擎报错 `Disabling a CollisionObject node during a physics callback is not allowed` | `set_deferred("process_mode", ...)` |
| 4 | 攻击朝向不对 | 判定盒朝上，靶子在右侧 → 打空 | 判定按 `facing` 旋转；测试先断言 `facing.x > 0.9` |
| 5 | GDScript 类型推断失败 | `var x := 未类型化返回值` → `Cannot infer the type`，脚本加载失败，进程挂起 | 用 `var x = ...` 或显式标注；测试加 watchdog 防挂死 |
| 6 | `--headless` 下 `save_png("res://...")` | 静默失败 | 用绝对路径 + 真实窗口（headless 不渲染） |
| 7 | 事件驱动输入无法自动化测试 | `Input.action_press()` 不产生 `InputEvent` | 全部改轮询 `is_action_just_pressed` |
| 8 | 导出模板缺失 | `--export-release` 报找不到模板 | 安装 `4.7.2.stable` 模板；只需解 `version.txt` + `windows_*x86_64` |
| 9 | 中文显示为方块 | 默认字体无中文字形 | `SystemFont`（Microsoft YaHei 等）做占位主题；发行前换 OFL 字体（思源宋体） |
| 10 | 把 `.import` 当生成物忽略 | 换机器后贴图过滤/压缩设置全丢 | `.import` 必须入库；只忽略 `.godot/` |
| 11 | 出包把测试脚本打进去 | 包体变大且暴露测试 | `exclude_filter="tests/*, _shot*.png, _smoke.log"` |
