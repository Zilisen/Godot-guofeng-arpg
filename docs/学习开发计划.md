# 国风动作肉鸽 · 教学版开发计划（从当前工程到 itch.io Demo）

> 工程：`D:\godot-guofeng-arpg`（Godot 4.7.2-stable，GDScript）
> 适用对象：有编程经验、但第一次做游戏
> 投入：8–10 h/周
> 预算：**≤100 元**（本计划默认 0 元）
> 定位：**亲手走完一遍完整流程**，不追求好玩、不追求商业成功
> 文档性质：可逐项打勾的清单。技术细节查 [制作流程文档.md](制作流程文档.md)；本文只回答"先做什么、怎么做、做到什么算完成"。

## 0. 先说清楚三件事

1. **不从"新建项目"开始。** 工程里已经有一个能跑、能出包的垂直切片：3 个房间循环、三段普攻、闪避（含无敌帧）、1 个技能、命中停顿、受击闪白/击退、震屏、输入缓冲、攻击取消窗、F1/F2 调试可视化、Windows 导出。本计划是在它上面**加内容、补流程**。

3. **不教你写代码语法。** 你有编程经验，缺的是"游戏工程怎么组织、在编辑器里点哪里、改完怎么验证"。所以每个阶段的重心是：**看懂现有结构 → 小改一处 → 跑起来看到变化**。

### 2.4 三条硬规则

1. **同一时间只有一个人改工程。** 你要自己改文件前，先告诉我改哪个；我改的时候你别同时开着改，避免互相覆盖。

3. **一次只动一个变量。** 同时改 5 个参数，跑出来不对，没人知道是哪个造成的。

## 5. 阶段详情（逐项打勾）

### S0 · 环境与第一次运行（2 h）

**阶段目标**：能独立打开工程、运行、开关调试、改一个参数并看到差异。

**要理解的概念（人话版）**
- **工程**：一个文件夹，Godot 认 `project.godot` 这个文件。
- **场景**：一堆积木（节点）拼好的整体，可以整体复用。`main.tscn` 就是主场景。
- **运行**：F5 跑的是"主场景"；F6 只跑你当前打开的场景（容易缺东西，先别用）。
- **检查器（Inspector）**：选中节点后，右边改它属性的地方。带 `@export` 的变量会出现在这里。

**具体操作**：见第 3 节"第一步清单"。

**验收标准**
- [ ] 能打开工程并 F5 运行
- [ ] 能操作 F1/F2，并说出红/蓝/青分别是什么
- [ ] 能独立完成一次"改 `Move Speed` → 保存 → 运行 → 改回"
- [ ] 发了第一份反馈（2.3 模板）

**常见坑**：见第 3 节表格。

### S1 · 看懂一个场景（3 h）

**阶段目标**：把"屏幕上的角色"和"场景树里的节点/脚本"对应起来，知道以后改东西该去哪找。

**要理解的概念**
- **节点树**：场景里所有东西的父子关系。父节点动，子节点跟着动。
- **场景实例**：`main.tscn` 里的 `Player` 是从 `player.tscn` 复制出来的一个实例；改 `player.tscn` 会影响所有实例。
- **脚本**：挂在节点上的"大脑"。`player.gd` 控制玩家。
- **信号（signal）**：节点之间"喊话"。比如玩家死了会发 `died`，主流程收到后弹结算。
- **碰撞层/掩码**：决定"谁能撞谁、谁能打到谁"。玩家的攻击只打敌人，就是靠这个。

**具体操作**
- [ ] 打开 `scenes/main.tscn`，展开 `Main → World → Player`，点 `Player`，看右侧 Inspector 的导出分组（移动/闪避/输入手感/受击/攻击）。
- [ ] 双击 `scenes/player/player.tscn`，找到 `AttackHitbox` 节点，看它的 `CollisionShape2D` 尺寸（280×190）。
- [ ] 打开 `scenes/game/room.tscn`，找到右侧的 `Door`，看它的 `Area2D` 和 `Fill`。
- [ ] 运行游戏，在「远程 / Remote」场景树里点 `Player`，对照 Inspector 看实时数值。
- [ ] 打开 `scripts/world/room.gd`，找到 `_set_door_open`，理解"清怪后开门"是哪几行。
- [ ] 打开 `scripts/actors/player.gd`，只看 `enum State`、`_poll_input`、`_update_free` 三个地方，不用全懂。

**验收标准**
- [ ] 能指出：玩家攻击判定盒、玩家受击盒、门、敌人出生点分别在哪个场景/节点
- [ ] 能解释"为什么改 `player.tscn` 会影响每一间房里的玩家"
- [ ] 能在运行中的 Remote 树里找到 Player 并看到实时 `state`
- [ ] 能说出玩家死亡后是谁在弹提示（`main.gd` 的 `_on_player_died`）

**常见坑**
| 坑 | 后果 | 避免 |
|---|---|---|
| 分不清"场景"和"实例" | 以为改 main 里的 Player 就行，结果下一间房变了又变回去 | 要长期改的，改 `player.tscn` 源场景 |
| 在运行中改场景 | 停止后改动丢失 | 先 F8 停止再改 |
| 乱改碰撞层 | 打不到敌人 / 穿墙 / 敌人不动 | 改前截图，改后跑冒烟测试 |

### S2 · 手感参数与攻击资源（4 h）

**阶段目标**：理解"手感 = 一组可调数字"，能自己调出 3 个可描述的差异。

**要理解的概念**
- **导出变量（@export）**：写在脚本里、显示在 Inspector 里，改完不用动代码。
- **资源（.tres）**：一份可复用数据。`light_1.tres` 就是"第一段普攻"的全部帧数据。
- **前摇 / 判定 / 后摇**：出手前的准备、真正能打到人的时间、收招硬直。
- **取消窗**：后摇进行到某个时间点后，可以被闪避/技能打断。没有它，连招会很黏。
- **无敌帧**：闪避开始后的一小段时间内，受击盒拒绝伤害。
- **命中停顿（hitstop）**：打中的一瞬间，双方定住几十毫秒，让打击"有重量"。

**具体操作（每次只改一个，改完 F5 体感，记录一句）**
- [ ] 把玩家 `dash_iframe_end` 从 `0.14` 改成 `0.20`，感受闪避是否更"无脑"；改回。
- [ ] 把 `light_1.tres` 的 `cancel_from` 从 `0.16` 改成 `0.10`，感受连招是否更顺/更飘；改回。
- [ ] 把 `light_1.tres` 的 `hit.hitstop` 从 `0.06` 改成 `0.12`，感受打击重量；改回。
- [ ] 把 `room_1.tres` 的 `enemy_speed` 从 `300` 改成 `420`，感受压迫感；改回。
- [ ] 在 `light_3.tres` 里改 `damage` 从 `24` 到 `40`，打敌人看血条掉得更快；改回。
- [ ] 记录一张小表：参数 → 改前 → 改后 → 一句话感受。

**验收标准**
- [ ] 能独立找到任意一个手感参数在哪个文件/节点
- [ ] 能说清"前摇/判定/后摇/取消窗"分别影响什么
- [ ] 完成 5 组对比记录，每组一句人话结论
- [ ] 改回原值，冒烟测试仍全过（我帮你跑）

**常见坑**
| 坑 | 后果 | 避免 |
|---|---|---|
| 一次改多个参数 | 不知道是哪个起的作用 | 一次只改一个 |
| 改 `.tres` 忘了保存 | 运行的是旧数据 | 改完 Ctrl+S，看标题栏有没有 `*` |
| 把 `hitstop` 调很大（>0.2） | 像卡顿，不像打击 | 0.04–0.12 之间试 |
| 把无敌帧调到覆盖整个闪避 | 游戏变简单，失去博弈 | 留 20%–30% 的"可被打"尾巴 |

### S3 · 自己加内容：第 4 间房 + 攻击变体（3 h）

**阶段目标**：第一次不写代码，只靠复制资源 + 改数值，给游戏加内容。

**要理解的概念**
- **数据驱动**：内容不是写死在代码里，而是放在 `.tres` 里。加房间 = 加一个文件 + 挂到列表。
- **类型化数组**：`run_config.tres` 里的 `rooms` 只能放 `RoomData`，拖错类型放不进去。
- **资源引用**：场景/资源之间用"路径引用"连接，移动文件会让引用断掉（Godot 会提示）。

**具体操作**
- [ ] 在文件系统里复制 `resources/rooms/room_3.tres`，重命名为 `room_4.tres`。
- [ ] 双击 `room_4.tres`，改 `display_name` 为「藏经阁」、`enemy_count` 为 `4`、`enemy_health` 为 `50`、`enemy_speed` 为 `240`。
- [ ] 双击 `resources/run_config.tres`，把 `room_4.tres` 拖进 `rooms` 数组末尾（顺序就是游玩顺序）。
- [ ] F5 跑一遍：HUD 应显示「第 1 / 4 间」，能连续走完 4 间。

- **断点**：在脚本行号左边点一下出现红点，运行到那里会暂停，可以看变量。
- **冒烟测试**：一组自动跑的断言。它不能证明"好玩"，但能证明"没改崩"。

**具体操作**
- [ ] 运行游戏，打开底部「输出 / Output」面板，看正常启动时的日志。

- [ ] 在 PowerShell 跑一次冒烟测试：


**验收标准**
- [ ] 能独立复制一段完整报错（含 `res://...:行号`）发给我
- [ ] 会用 `print` 打印一个变量并读懂
- [ ] 会下断点并查看变量

**常见坑**
| 坑 | 后果 | 避免 |

## 6. 阶段依赖与"跳过会怎样"

### 6.1 依赖图

```
S0 环境
 └─ S1 场景/节点
     ├─ S2 参数/资源
     │   └─ S3 加房间/攻击
     │       ├─ S4 敌人差异
     │       │   └─ S9 词条 ──→ S10 Boss（数值/平衡）
     │       └─ S9 词条（需要 AttackData/Player 参数）
     ├─ S5 调试（可与 S2 并行，但最晚 S6 前完成）
     ├─ S6 一局流程 ─→ S7 存档 ─→ S8 UI ─→ S12 发布
     └─ S8 UI
S10 Boss ─→ S12 发布
S11 美术/音效：任意时间插入，不阻塞任何阶段
```

### 6.2 跳过后果表

| 阶段 | 能否跳过 | 跳过的后果 |
|---|---|---|
| S0 | ❌ 不能 | 后面所有"验收"都无法进行 |
| S1 | ❌ 不能 | 改场景时容易改错实例、丢改动，返工率高 |
| S2 | ❌ 不能 | 后面每个阶段都要调参数，不会调等于寸步难行 |
| S3 | ⚠️ 不建议 | 资源工作流是 S9 词条的基础；跳过会让你后面只能看我改，失去练手 |
| S4 | ⚠️ 可压缩 | 只压缩到"看懂状态 + 改 RoomData"（2 h）可以；完全跳过会把理解成本推到 Boss 阶段 |
| S5 | ❌ 不能（可提前） | 不会看报错，后面每次卡住都要等我，节奏会碎 |
| S6 | ❌ 不能 | Demo 必须有完整一局 |
| S7 存档 | ⚠️ 可跳但会返工 | 跳过 → S8 设置无法保存、Demo 每次从头；后补要改 UI 和主流程，约返工 3–5 h |
| S8 UI | ❌ 不能 | 没有菜单/暂停/设置的包不能算 demo |
| S9 词条 | ❌ 不能 | Roguelite 的核心就是构筑；跳过就只是动作游戏 |
| S10 Boss | ❌ 不能 | 用户明确要求一个 Boss；也是全流程的收尾 |
| S11 美术/音效 | ✅ 可跳过 | **不返工**，只影响观感；几何占位也能发布 |
| S12 发布 | ❌ 不能 | 目标就是"能下载的 demo" |

**一句话原则**：**跳过"理解类"阶段（S1/S2/S5）会拖慢后面所有阶段；跳过"表现类"阶段（S11）只影响观感。**

## 9. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 某阶段卡住超过 1 周 | 中 | 节奏断 | 拆成更小步；先跳过非核心（S11），核心阶段我直接给可运行版本 |
| 词条/存档改崩 | 中 | 前功尽弃 | 每阶段 git 提交；改完跑 43 项冒烟 |
| Boss 平衡反复 | 高 | 拖时间 | 先"能打"再"好玩"；数值先粗调，发布前不再大改 |
| 美术/音效找不到满意的 | 高 | 拖延 | 直接跳过 S11，几何占位发布 |
| itch 上传/下载出问题 | 低 | 无法发布 | 保留本地 zip；必要时换 GitHub Release 托管 |
| 8–10 h/周实际达不到 | 高 | 延期 | 按 12 周排；每周只保一个"可验收"小目标 |

## 10. 术语小词典（忘了就回来查）

| 词 | 人话 |
|---|---|
| 节点 Node | 游戏里的一个"零件"，比如一张图、一个碰撞体、一个计时器 |
| 场景 Scene | 拼好的一组节点，可整体复用（玩家、房间、UI 都是场景） |
| 实例 Instance | 把场景放进另一个场景后的那个副本 |
| 脚本 Script | 挂在节点上的逻辑，GDScript 写的 `.gd` |
| 信号 Signal | 节点之间的事件通知，比如"我死了" |
| 导出变量 @export | 显示在 Inspector 里、可直接改的脚本变量 |
| 资源 Resource | 可复用的数据文件，`.tres` |
| Hitbox / Hurtbox | 攻击判定盒 / 受击判定盒 |
| 无敌帧 i-frame | 一段时间内不接收伤害 |
| 前摇/后摇 | 出招前的准备 / 出招后的硬直 |
| 取消窗 | 后摇中允许被其他动作打断的时间点 |
| Hitstop | 命中瞬间双方短暂定住，制造打击感 |
| 冒烟测试 | 一组自动断言，确认"没改崩" |
| `user://` | 存档等用户数据的目录，导出后可写 |
